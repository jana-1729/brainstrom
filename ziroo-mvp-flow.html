Ziroo · MVP · Hybrid: Spec-Rendered UI + Generated Backend

Chat → App — Complete Architecture Flow

One sentence in chat becomes a governed, versioned, SSO'd internal app. Companion to ziroo-mvp-architecture.md and the phase plans.
The core split: the frontend is never generated — the AI emits and patches a PageSpec (layout tree · widget configs · theme tokens) that our Page-Gen Engine (one Next.js + shadcn renderer) interprets. Theme change = token patch → CSS variables. "Move this block" = layout patch → live reflow. Only the app's Convex backend is code-generated, inside template rails.

I · Component Map — who exists and who talks to whom

Control plane (Ziroo Core) orchestrates and owns the PageSpec; the build plane (worker) generates only backend code; ONE renderer serves every app via wildcard subdomains, subscribing to each app's Convex for spec + data. Generated code runs only in Convex sandboxes; the renderer runs only our code — app behavior reaches it as validated data.
Ziroo-built (bold border) managed platform / flow trust relation (JWT · routes)

II · The Create Flow — 36 numbered steps, chat to live app

The Jira-analytics walkthrough end-to-end. The par block is the pivot made visible: backend plan (for codegen) and PageSpec (UI as data) come from one Brief, bound by a query-name contract the verifier enforces. Dashed returns are async; the grey band is the provision burst; connect-pause and self-heal are first-class states.
1–6 · Understandintent → app-builder tool → ≤3 sharp questions → App Brief JSON (entities · sources · pages · roles) — the semantic record everything else derives from.
7–13 · CredentialsPipedream account check. Missing → Connect card, build parks, OAuth, resume. Ziroo never stores tokens — only account_id references.
14–15 · Plan, both halvesbackend plan (schema · function names · crons) ∥ PageSpec (layout · widgets bound to those names · theme). One pass, no drift.
16–19 · Provisionbackend repo from template · Convex project + key · subdomain routed to the renderer (a domain attach, not a project). Streamed as stages.
20–24 · Generate & verifycoding agent writes backend only, inside AGENT_RULES rails; typecheck + binding check (PageSpec ⊆ function-spec) with ≤2 self-heal rounds; preview deploy + headless render smoke.
25–26 · Approveplain-English card — stores what · who sees what · external scopes · clickable preview (draft spec on preview backend). Never a code diff.
27–33 · Shipmerge, tag v1, Convex prod deploy, publish PageSpec to the app's pages table, first cron sync through the server-side proxy. Live URL in chat.
34–36 · UseSSO via Ziroo JWT; renderer subscribes to spec + data — reactive, role-gated, LLM-free at runtime.

III · The Edit Fast Path — why the spec-rendered UI wins

Cosmetic and layout edits never touch codegen, builds, or deploys: patch → validate → publish → every open session restyles/reflows live. Seconds, versioned, undoable. Anything touching roles or data takes the full pipeline with the human approval gate.
